# 왁뿌볼 (Wakppu Ball) 기술 스택 및 배포 절차

## 1. 전반적인 기술 스택 확정 (제안)

'토스 바이브(Toss Vibe)'의 유려하고 인터랙티브한 UI와 포켓몬 카드와 같은 화려한 CSS 효과를 구현하기 위해 다음과 같은 기술 스택을 제안합니다.

### Frontend (시각/인터랙션)
*   **프레임워크:** **React** 또는 **Next.js** (웹뷰 기반 앱인앱 개발에 적합)
*   **인터랙티브 렌더링 (왁뿌볼 시뮬레이션):**
    *   **Three.js / React Three Fiber:** 3D 기반의 질감과 물리엔진을 적용한 슬라임 형태를 구현할 경우
    *   *(대안)* **HTML5 Canvas API / WebGL Shaders:** 2D 기반에서 쫀득한 유체 효과나 왜곡 필터를 구현할 경우
*   **스타일링 & 애니메이션:** **Tailwind CSS**, **Framer Motion** (토스 바이브의 매끄러운 화면 전환)
*   **감각 피드백 (촉각/청각):** Web Audio API (ASMR 사운드 재생), Navigator.vibrate API (진동 피드백)
*   **상태 관리:** Zustand (포인트, 보유 왁뿌볼 상태 등 전역 관리)

### Backend & Database (필요 시)
*   **BaaS:** **Supabase** 또는 **Firebase** (초기 개발 속도를 높이고 사용자 인증, 포인트, 레벨 시스템을 빠르게 구축하기 위함)

## 2. 토스 앱인앱 배포 절차 (초안)

> **안내:** Notion 페이지에 접근이 제한되어 일반적인 웹뷰 기반 앱인앱(미니앱) 배포 절차를 바탕으로 작성했습니다. 노션에 정리해두신 **'토스 바이브코딩 앱인앱 출시 가이드'**의 구체적인 내용을 공유해주시면, 해당 가이드에 맞춰 배포 절차를 정확하게 업데이트하겠습니다.

1.  **웹 서비스 개발 및 최적화:** 모바일 웹 환경(웹뷰)에 완벽하게 대응하도록 반응형 웹으로 개발하고, 렌더링 성능을 최적화합니다.
2.  **호스팅 및 도메인 연결:** Vercel 등을 통해 개발된 웹 앱을 배포하고 HTTPS를 지원하는 도메인에 연결합니다.
3.  **토스 미니앱 연동 심사 준비:** 토스 앱 내에서 웹뷰 형태로 띄우기 위한 URL을 준비하고, 앱인앱 가이드라인(UI/UX, 보안 등)을 준수하는지 검토합니다.
4.  **토스 측 제출 및 심사:** 토스 개발자 센터나 제휴 채널을 통해 서비스 URL 및 필요 정보를 제출하여 심사를 받습니다.
5.  **라이브 배포 및 모니터링:** 심사 통과 후 라이브로 전환되며, 초기 MAU 확보와 성능 이슈를 모니터링합니다.
